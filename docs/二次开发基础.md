## Windows 本地启动

1. 安装 Node.js，版本须满足 `^20.19.0 || >=22.12.0`；安装包自带 npm。当前机器已检测到 Node.js 22.20.0、npm 10.9.3。
2. 打开 PowerShell，执行：

   ```powershell
   cd D:\BcFolder\BCweb\mascot-content-studio\web
   npm install --legacy-peer-deps
   npm run dev
   ```

3. 浏览器访问 <http://localhost:3000>。结束时在运行服务器的终端按 `Ctrl+C`。当前机器已通过下方恢复步骤重新安装依赖，Vite 已报告启动成功；页面功能仍待用户自行检查。

上游的 `@ant-design/pro-components` 声明依赖 Ant Design 5，而项目使用 Ant Design 6，普通 `npm ci` 会报 peer dependency 冲突。`--legacy-peer-deps` 是绕过 npm 的 peer 检查，不代表已验证两者兼容。上游的 `package-lock.json` 还没有包含 `package.json` 中的 `i18next` 和 `react-i18next`，因此不能假定加参数后的 `npm ci` 可以使用；上述 `npm install` 会更新该锁文件。上游 README 使用 Bun：若已安装 Bun，也可在 `web/` 中执行 `bun install` 和 `bun run dev`，此方式同样尚未在本机验证。

如果 Windows 安装缺少 Rollup、esbuild 等平台原生依赖，可在 `web/` 执行下列命令，将现有依赖和锁文件移动到项目同级的时间戳备份目录，再重新生成锁文件并安装：

```powershell
$backupPath = "D:\BcFolder\BCweb\mascot-npm-backup-$(Get-Date -Format 'yyyyMMdd-HHmmss')"
New-Item -ItemType Directory -Path $backupPath
Move-Item -LiteralPath .\node_modules -Destination $backupPath
Move-Item -LiteralPath .\package-lock.json -Destination $backupPath
npm install --legacy-peer-deps --include=optional
npm run dev
```

重新生成锁文件可能选取与原先不同的依赖版本；备份可用于恢复原安装状态。本机已执行此恢复步骤，原依赖及锁文件保存在同级 `mascot-npm-backup-20261027-092411`。

上游 `dev` 脚本默认监听 `0.0.0.0:3000`，即所有本机网络接口，并不只监听本机回环地址；Vite 遇到端口占用时可能自动选择其他端口，以终端显示的地址为准。如只希望本机访问，可用 `npm run dev -- --host 127.0.0.1` 启动。

可自行查看首页 `/`、画布 `/canvas`、图片工作台 `/image`、素材 `/assets`、提示词 `/prompts` 和配置 `/config`。首次使用默认中文；若浏览器已保存上游语言选择，则沿用已保存的语言。查看页面不需要配置模型或提交生成请求。

## 当前边界

- 上游源码包含生图、视频、画布、插件、Agent 和其他入口；保留源码不代表本站已完成各项功能验收或决定正式开放。
- 本站图片服务、受保护的服务端密钥、账户登录、云端作品及用户数据隔离均未接入。上游默认把渠道配置、API Key、画布、素材和生成记录保存在浏览器本地，并由前端请求外部接口；不应将其视为本站的服务端账户系统。
- 部分上游功能需要用户自行配置外部服务，或单独启动本地 Agent / 代理；仅启动 Web 不会接通这些服务。不要为了查看界面配置密钥或发起模型请求。
- 原 Astro 的 `src`、`dist`、`.astro` 和相关本地缓存已移入回收站。其同级备份 `mascot-content-studio-astro-backup-2026-10-27` 仍保留依赖目录、原 README、配置文件、`.env.example`、Supabase 迁移及文档；未迁移到新应用，也未执行数据库迁移。两份项目定义文档已放回当前仓库 `docs/`。
- 已重新安装依赖，Vite 报告在本机 3000 端口启动；尚未进行页面验收、测试、构建、类型检查、真实模型调用或部署。
