# Infinite Studio 差异化方向：二次调研与验证建议

调研日期：2026-11-05。决策更新：2026-11-06 已选择方向 1「图解跟着资料改」，并更新[产品定位与范围](产品定位与范围.md)、[首版设计与验证计划](plans/2026-11-06-source-linked-diagram-design.md)及[自部署迁移路线](开源自部署目标与迁移路线.md)。下文保留调研时的公开材料、判断和验证建议；方向确定不代表需求或效果已验证，真实案例与对照试验仍待完成。

## 建议先验证什么

**先验证「资料变了，成品只改该改的地方」：给需要维护中文科普或培训图解的小团队，一个可自部署的修订工作台。** 首个交付物是一张可编辑的机制图和它的发布版 PNG。资料变更时，工作台给出受影响的图上对象及原文，用户预览并确认修改；已确认且不受影响的图层保持原样。

例如，中文版讲稿把某设备的“预热 30 秒”更正为“预热 45 秒”。工作台指出流程图上的步骤标签和脚注需要核对，展示旧值、新值和出处；编辑确认后只更新这两个对象，并能找回旧版。若原文删除或存在冲突，标记待核对，保留原稿，不猜测新结论。这个示例用于说明交互，不是已发生的客户案例。

上一轮的 NAS 持久化、备份与迁移仍是自部署的交付要求。[上一轮报告](AI创作工具市场与开源竞品调研-2026-10-30.md)记录了实际请求，但已有二开覆盖相邻功能。首页应该先演示一次让创作者少返工的修订，再解释项目如何部署和保存。

## 市场与开源样本

本轮抽样横跨商业创作平台、中文自部署工作台、生产管理、游戏资产和知识图解。下表来自官方文档、仓库、发行说明、论文和公开 issue；未安装竞品或进行生成对跑。未查到某能力不等于竞品不支持，也不据此推断市场规模。

## 三个方向的取舍

| 优先级 | 用户与可见交付 | 为什么排在这里 | 什么结果会否定它 |
| --- | --- | --- | --- |
| 1. 图解跟着资料改 | 中文科普、培训团队；交付带来源定位的可编辑图和 PNG，用于现有短视频或文档。 | 已有知识短视频可找真实修订样本；范围能收窄到一张图。以手工编辑、Paper2Any 和 PaperBanana-Interact 作对照。 | 实际很少返修；手工编辑更快；建来源链接耗时超过节省；或系统漏掉影响含义的变动。 |
| 2. 给现有 Cocos 项目安全换图 | 独立游戏开发者；替换一个已有 UI 入口图标，保留引用，并交付改动清单、回滚方式及预览结果。 | CatInBox 可提供真实样本，能明确检查资产身份、点击区域和窄屏布局；Copilot 已高度重叠。 | 在工程副本中，Copilot 或现有编辑器能用同等步骤可靠完成，就优先用现成能力；若仅剩一个缺口，做插件，不扩成工作台。 |
| 3. 审定内容变更后同步成套物料 | 小型内容团队；交付同一图解的横版和竖版，列出各自需要重审的元素。 | 有直接成品价值，但 TAKEGRAPH 已做选择性重建，Vellum 已做版本审批，Scenario 已做工作流应用。把它视为方向 1 的后续试验。 | 现成工作流加手工核对能达到同样质量和耗时，或团队没有跨尺寸同步需求，就不做通用引擎。 |

## 先用真实任务验证方向 1

1. **找出 3 个真实变更。** 从已有科普制作记录挑选初稿、改动前后的资料、最终交付图；覆盖数值修正、定义/关系变化、来源删除或冲突。逐例事先标注应改对象、必须保留对象和必须人工判断的内容。找不到真实改版记录，就先不投入开发；演示样例只能验证交互。
2. **同题对照。** 用当前手工编辑流程作强基线，再选一个能导出可编辑对象的近邻；将 PaperBanana-Interact 的多轮生成作为可运行时的附加对照。各组都拿到相同的两版资料、图和验收清单；比较从首次导入、建立关联到交付的总耗时，以及第二轮的单次修订耗时。记录漏改、误改、外部模型调用和人工核对步骤；无法运行的竞品只作公开能力对照，不能计成输家。
3. **把原型限制在一个流程。** 首次导入固定格式的中文资料，手工确认来源段落和对象绑定；用一类可编辑流程图验证“资料差异 → 受影响对象 → 前后对比 → 人工确认 → 导出”。建议用本地清单和现成 SVG 渲染先做，稳定 ID 对照未受影响对象的内容和样式；允许自动排版时预览布局变化。遇到语义改写、冲突或找不到原段落，交给人工判定。复用当前图片生成、参考图和画布做素材草稿，关联和修订规则需要新做；无需等待生产后端完成才验证体验。
4. **预先设定继续条件。** 建议试验门槛：3 个真实案例中至少 2 个相对最快可行基线的总人工耗时下降 30%，全部案例均无关键事实漏改、无未批准对象变动，且两位非开发试用者各愿意拿下一份真实资料再试。样本很小，过线只支持继续验证；若只有第二轮省时，先计算第几轮能收回建链成本；若实际达不到该频率或效果，缩减为辅助功能或停止。

调研时仓库已有图片生成、参考图、复用与历史界面；模板仍主要是字段拼接，生成接口走 Vite 开发中间件，画布与创作数据仍有浏览器持久化依赖。方向 1 的来源绑定、结构化对象与受控修订均未实现。2026-11-06 已将先验证、后生产交付的顺序写入[开源自部署目标与迁移路线](开源自部署目标与迁移路线.md)；具体项目格式仍需通过小样本验证后再纳入生产实现，对外发布前仍需独立验证生产运行、备份恢复和发行许可。
