# 开源自部署目标与迁移路线

状态：2026-11-06 更新。当前产品方向已确定为[「图解跟着资料改」](产品定位与范围.md)，先用真实任务验证单图修订，再推进生产交付。2026-10-29 确定的中文优先、自部署、部署机本地保存和备份迁移要求继续有效。以下架构为推荐方案，除明确标明的现状外均未实现或验收；此前以海外托管平台和云存储为前提的架构不再作为实施依据。

## 目标和边界

- 开源、自部署、中文优先；使用者能够获取源码，按文档运行、升级和备份。
- 项目数据保存在部署机器本地，包括资料版本、图解对象、来源关联、修订记录与导出版本，以及现有项目、画布、创作记录、素材、收藏、设置和任务状态；浏览器缓存不能是唯一副本。部署机器可以是个人电脑，也可以是用户自行管理的服务器。
- 首个产品闭环是单张中文机制流程图的来源关联、影响定位、人工确认局部修订和版本化导出。自由提示词、模板、参考图和画布作为素材创作基础；多尺寸同步和视频能力后续单独验证。
- 开箱体验指无项目方账户或项目方托管云依赖即可启动、浏览和管理本地内容；使用外部模型时需自行配置可用服务、密钥并承担费用。不能承诺任意供应商或模型均兼容。
- 用户选择外部 AI、远程提示词、插件或其他服务时，相关数据可能发送到该服务。区分“本地持久化”与“完全离线”，说明目的地和内容。
- 多用户隔离、公开互联网部署和高可用不属于首版默认支持范围；支持前需要先实现和验证身份认证、授权及其他安全边界。

## 已核对的实现差距

| 范围 | 当前代码 | 与目标的差距 |
| --- | --- | --- |
| 图解修订 | 当前无来源绑定、结构化图解对象和受控修订实现 | 先按[首版设计与验证计划](plans/2026-11-06-source-linked-diagram-design.md)验证本地项目格式及单图流程，再将有效格式纳入生产存储。 |
| 创作、素材与收藏 | `apps/web/src/image-studio.tsx` 和 `prompt-library.tsx` 使用 IndexedDB | 换浏览器或清除站点数据可能丢失；需迁移至部署机本地存储并提供旧数据导入。 |
| 画布 | 集成的 `apps/canvas` 使用浏览器本地存储 | 项目及引用素材须完整迁移；先验证上游数据结构和导入导出。 |
| 模型配置和调用 | Vite 开发中间件保存本地密钥并代理请求 | 配置文件在部署机，但接口只在开发服务中运行，密钥明文存储；没有可交付的生产服务。 |
| 旧云代码 | Worker、Supabase 账户及迁移仍在仓库 | 不应成为运行必需项；逐步替换、清理，避免遗留入口误导用户。 |
| 外部访问 | 提示词库获取远程数据和图片；画布包含更新检查、远程插件等功能 | 盘点默认请求，提供开关或本地替代。第三方统计当前默认关闭，不等于完全无网络请求。 |
| 许可证与发布 | 已保留画布和 Toonflow 许可文件，根目录无项目许可证 | 需选定本项目许可和版权声明，审查依赖、字体、图标、图片及提示词的独立条款。 |

现有功能效果取决于配置、上游与网络；历史测试不能替代新部署目标的验收。

## 建议架构与决策

### ADR 1：本地单体服务

建议 React 前端由一个 Node.js 服务提供静态资源与同源 API；服务端管理配置、项目数据、媒体文件和模型适配。默认仅监听回环地址，提供健康检查和清晰的启动错误。数据目录可配置，默认位置应明确且易备份，与程序和构建产物分离。

备选纯浏览器实现安装简单，但不符合“数据在部署机器、可统一备份”；继续依赖托管数据库或云对象存储会增加外部依赖，也不符合目标。单体比拆分多个服务更容易自部署；代价是需要自行维护迁移、进程、磁盘与备份。

### ADR 2：数据与媒体

建议先验证 SQLite 保存结构化记录、版本化 schema，媒体存放在同一数据目录下的文件子目录；记录使用稳定 ID 引用媒体。明确事务、并发、文件写入失败和中断恢复策略，避免数据库记录与媒体文件不一致。与全部使用 JSON 文件相比，SQLite 更适合结构化查询和迁移，但数据库备份必须考虑一致性；相较独立数据库，它更便于单机部署，但不应假定适合高并发多实例。

图解原型先以版本化 JSON 清单和 SVG 渲染验证资料、对象、来源关联及修订记录，不要求提前迁移全部现有功能。通过效果验证后再确定生产 schema；原型文件不是统一部署机存储的完成证明。生产迁移须保留稳定 ID、原文快照、人工确认记录和历史版本，导出与恢复后仍能返回对应来源。

备份必须保证数据库和媒体的一致性：采用经过验证的在线备份方案，或停机后备份；生成清单、版本信息和完整性校验。恢复前验证版本、保留原数据并提供冲突处理。备份默认不含密钥；如支持包含凭据，须明确告知并保护备份。需要提供从旧浏览器数据导出、校验、导入、重试与结果核对的实际工具，并保留原始数据直到用户确认。

### ADR 3：配置与密钥

部署配置覆盖监听地址、端口、数据目录、日志级别、功能开关、模型地址和超时等；创作设置覆盖模型及其支持的参数；提示词和模板支持本地管理及导入导出。提供配置示例、默认值、校验、重启生效规则和错误提示；参数以实际需求为准，避免无约束配置。

密钥只由服务端读取，不返回前端、不进入日志和仓库；提供替换及删除方式，并说明权限和明文存储风险。支持环境变量或受限权限的本地配置文件；不要把可逆编码描述为加密。远程访问和多用户模式需要独立设计身份认证、授权、传输保护、请求来源校验和安全部署，未验证前不对公网开放。

### ADR 4：外部服务与插件

基础浏览和本地数据管理不依赖项目方云服务。外部模型请求由部署者主动配置；提示词远程来源、更新检查、插件注册表、统计和远程图片要逐项清点，默认和开关行为需在文档中明确。插件可能执行代码并读取数据，安装、启用和权限风险需要明确提示，不能默认信任。

提示词及示例素材优先使用允许分发且已注明来源的内容，或提供空库和本地导入；不能直接把远端内容打包视为已获许可。外部服务断开时不应破坏本地数据。

## 实施顺序

### 先验证产品价值

1. **真实样本与基线**：收集数值修正、定义或关系变化、来源删除或冲突这 3 类真实案例，预先标注应改、应保留和待判断对象；运行并记录手工流程及可行近邻的耗时。找不到真实记录时先积累样本，不启动功能开发。
2. **单图原型**：用本地清单和现成 SVG 渲染实现来源绑定、资料差异、影响清单、前后预览、人工确认、版本恢复和导出；明确处理未关联变更及不确定来源。无需等待生产后端，但不能将原型当作可发布的自部署产品。
3. **继续判断**：3 例至少 2 例比最快可行基线减少 30% 总人工耗时，全部案例无关键事实漏改、无未批准对象变动，两位非开发试用者各愿意拿下一份真实资料再试。总耗时包含首次导入与建链；仅后续轮次省时需核算成本回收轮数。未达到时缩减为辅助功能或停止，达到仅支持继续验证。

案例、交互和验收约束见[首版设计与验证计划](plans/2026-11-06-source-linked-diagram-design.md)。

### 验证后完善生产交付

以下工作是对外发行前的要求，不作为开始单图体验验证的前置阻塞；试验中引入的代码与素材仍需有合法使用依据。

1. **确定发行基线**：选定根许可证和版权署名；盘点上游、依赖、提示词与素材许可；明确首版支持环境和模型协议。
2. **生产运行基础**：提供独立 Node 服务、同源静态资源、可校验配置和默认本机监听；生产请求不再依赖 Vite 开发中间件。
3. **本地持久化**：实现版本化数据库、媒体文件与统一数据目录；纳入验证后的资料、图解、来源关联和修订格式，迁移创作记录、收藏、素材和画布；实现并验证原型项目及浏览器旧数据迁移。
4. **模型与配置**：供应商适配、配置页面与密钥生命周期；区分未配置、连接失败、能力不兼容及请求结果未知等状态。
5. **自部署与恢复**：提供明确支持的运行方式及容器化部署方案，配置目录挂载、升级流程、备份恢复和排错说明，实测全新环境。
6. **发布质量**：完成许可证清单、贡献指南、安全问题反馈、版本与变更记录；覆盖基础测试、部署、迁移、恢复、离线和安全检查，再准备社区介绍。

每一步只在实际完成并验证后标记完成。上线论坛前应提供真实截图、运行要求、功能边界和已知问题，不将计划描述为已有功能。

## 发布验收

- 真实资料改版后可定位受影响对象和出处；核对未关联变更，批准后只修改已确认的对象集合。来源不明时保留旧稿并标记待核对，发布版不能冒充已完成核对。
- 保存并重新打开图解项目后，原文快照、对象 ID、来源关联和修订记录完整；可查看与恢复旧版本，导出的可编辑图与 PNG 对应同一已确认版本。
- 在干净环境按文档部署，未配置项目方云账号即可启动；重启及升级后项目、画布和素材仍完整。
- 配置一个明确支持的模型接口，完成生成、保存、重新打开和下载；断网时已保存内容仍可浏览，外部请求失败有明确反馈。
- 浏览器旧数据迁移后，项目数量、画布内容、图片引用和收藏可核对；模拟失败时旧数据不丢失。
- 在独立目录恢复备份，核验数据库、媒体、画布引用及版本；不覆盖原数据，默认不泄露密钥。
- 检查浏览器与服务端网络请求，记录默认外联与用途；第三方统计默认关闭，远程内容、插件及模型请求具有清晰控制和说明。
- 执行类型检查、构建、自动化测试，以及真实设备、安装和人工体验检查；记录系统版本和结果，不把构建成功等同于部署、安全或创作质量验收。
