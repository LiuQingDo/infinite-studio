# 产品定位与范围

状态：2026-11-06 确定当前方向为 **「图解跟着资料改」**，依据[二次调研与验证建议](差异化方向二次调研与验证建议-2026-11-05.md)。这是产品方向决策；真实需求频率、节省效果和实现可行性仍需验证，核心修订能力尚未实现。

## 产品方向

Infinite Studio 面向需要维护中文科普或培训图解的小团队，建设中文优先、可自部署的图解修订工作台。资料变更时，帮助创作者找到受影响的图上对象和原文，预览并确认修改，保留已确认且不受影响的内容与样式，并能找回旧版。

首个交付物是一张带来源关联的可编辑机制流程图及其发布版 PNG，可用于现有短视频或文档。产品首先验证的价值是减少资料更正后的返工；自部署、部署机本地保存、备份与迁移继续作为交付要求。

例如，资料将“预热 30 秒”改为“预热 45 秒”，工作台定位到步骤标签和脚注，展示旧值、新值与出处，编辑确认后更新对应对象。其他步骤的内容、样式和位置保持原样；需要重新排版时另行预览并确认。来源删除、冲突或语义不明时保留原稿并标记待核对。此例仅说明目标体验，不是客户案例或已有功能。

## 方向取舍

| 方向 | 决策 | 原因与后续条件 |
| --- | --- | --- |
| 图解跟着资料改 | 当前主方向，先验证一张图的修订闭环 | 可从现有知识内容制作寻找真实案例，检查哪些对象应改、哪些必须保留；来源关联的成本与收益可单独测量。 |
| 给现有 Cocos 项目安全换图 | 保留候选，不进入当前首版 | 与已有编辑器及插件能力重叠；若以后发现明确缺口，再考虑独立插件。 |
| 审定内容变更后同步成套物料 | 方向 1 验证后的扩展候选 | 先证明单图修订有效，再验证横竖版等多份物料是否有同步需求。 |

通用生图、模板、参考图和画布保留为现有素材创作基础。当前不以扩充行业模板、通用工作流引擎、视频制作或多用户协作为首版目标。

## 首版验证范围

- **输入**：固定格式的中文资料及其两个版本；首轮采用分段纯文本或 Markdown，不扩展任意 PDF、OCR、网页抓取。
- **图解**：一种可编辑的机制流程图；人工确认段落与对象的关联，图上对象具有稳定 ID。
- **修订**：资料差异 → 受影响对象和出处 → 修改前后预览 → 人工确认 → 新版本和导出。覆盖数值修正、定义或关系变化、来源删除或冲突；不确定的判断交给人工。
- **保留与追溯**：未批准的对象不得变动；每次确认保留资料版本、对象变化和旧图。布局变化也属于需确认的修改。
- **交付**：可继续编辑且保留来源关联的项目、可编辑图和 PNG。原型先用本地清单与现成 SVG 渲染验证；生产持久化在验证后按迁移路线实施。

具体流程图、页面交互及验收定义见[首版设计与验证计划](plans/2026-11-06-source-linked-diagram-design.md)。

## 继续投入的条件

1. 先找出 **3 个真实修订案例**，包含两版资料、改前图和最终交付图，预先标出应改对象、必须保留对象和需人工判断的内容。找不到真实记录时，先积累样本，不启动功能开发；演示样例只能验证交互。
2. 用当前手工流程及一个可运行的可编辑图解近邻作同题对照；PaperBanana-Interact 可运行时作为附加对照。比较包含首次导入、建立关联和最终核对的总人工耗时，同时单列第二轮修订耗时、漏改、误改和模型调用。无法运行的工具不计为落后。
3. 采用调研建议的继续门槛：3 例中至少 2 例比最快可行基线减少 **30% 总人工耗时**；全部案例无关键事实漏改、无未批准对象变动；**两位非开发试用者**各愿意用下一份真实资料再试。
4. 过线只支持继续验证。若仅第二轮省时，计算回收建链成本所需轮数；实际频率或效果不足时，缩减为辅助功能或停止该方向。

## 当前实现与交付边界

现有开发预览包含图片生成、参考图、结果复用、历史界面、提示词库和集成画布。来源绑定、结构化图解对象与受控修订尚未实现；图片历史不等于可追溯的图解修订版本。

当前图片接口依赖 Vite 开发中间件，创作记录和画布等数据仍有浏览器持久化依赖。统一部署机存储、生产服务、备份恢复和根许可证尚未完成。对外发布前须按[开源自部署目标与迁移路线](开源自部署目标与迁移路线.md)独立验收。

自部署不依赖项目方云账户；选择外部模型时，相关资料、提示词或参考图可能发送给该供应商。本地保存不代表完全离线。首版不默认支持公网多用户部署。
